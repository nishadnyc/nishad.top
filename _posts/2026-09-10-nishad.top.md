# Auto‑Generated Blog & Portfolio Powered by AI

## Overview

A modern personal blog and portfolio website that writes itself. By harvesting information from your public GitHub repositories and feeding it into an AI language model, the site automatically creates fresh, high‑quality blog articles every day. The entire pipeline runs on GitHub Actions, triggered by a cron schedule, ensuring your portfolio stays up‑to‑date with minimal manual effort.

## Purpose

- **Showcase Your Work** – Turn code, commits, and releases into readable stories that highlight your contributions and technical expertise.
- **Stay Visible** – Publish new content daily without lifting a finger, improving SEO and keeping visitors engaged.
- **Leverage AI for Content** – Use an advanced language model to transform raw repository data into polished prose, eliminating writer’s block.

## Core Architecture

| Component | Role |
|-----------|------|
| **GitHub Repositories** | Source of truth for projects, commits, releases, and README files. |
| **GitHub Actions (Cron Job)** | Executes a daily workflow that pulls repository data, invokes the AI model, and commits generated articles. |
| **AI Language Model** | Consumes repository metadata and crafts coherent, human‑like blog posts. |
| **Static Site Generator** (e.g., Hugo, Jekyll, Next.js) | Renders markdown articles into a fast, SEO‑friendly website. |
| **Deployment** (GitHub Pages, Netlify, Vercel, etc.) | Hosts the resulting site, making new articles instantly accessible. |

## Key Features

- **Daily Automated Content Generation** – A cron‑driven GitHub Actions workflow runs once per day, guaranteeing a steady stream of new posts.
- **Repository‑Driven Insights** – Extracts commit history, pull‑request summaries, issue tags, and README content to inform the AI.
- **AI‑Powered Writing** – Generates articles that explain project goals, challenges, solutions, and outcomes in a reader‑friendly tone.
- **Seamless Integration** – All steps are performed within the repository; no external servers or services are required beyond the AI API.
- **Markdown Output** – Articles are saved as markdown files, making them easy to edit, version‑control, and render.
- **Customizable Templates** – Define your own article structure, styling, and metadata (title, tags, cover image) to match your brand.
- **SEO Optimized** – Automatically includes meta tags, Open Graph data, and structured JSON‑LD for better search engine visibility.

## How It Works: The Daily Workflow

1. **Trigger** – GitHub Actions’ scheduler (`cron: '0 0 * * *'`) fires every 24 hours.
2. **Data Collection** – The workflow clones the repository, queries the GitHub API for:
   - Repository description
   - Recent commits
   - Open and merged pull requests
   - Issues and milestones
   - README content
3. **Prompt Construction** – A structured prompt, embedding the collected data, is sent to the AI model (e.g., OpenAI GPT‑4 or a comparable service).
4. **Article Generation** – The AI returns a markdown‑formatted article, complete with headings, code snippets, and a brief summary.
5. **Post‑Processing** – Optional linting and formatting ensure consistency with the site’s style guide.
6. **Commit & Push** – The new article file is committed back to the `posts/` directory (or equivalent) and pushed to the repository.
7. **Site Build** – A separate GitHub Pages or Netlify build step regenerates the static site, publishing the fresh content.

## Getting Started

1. **Clone the Repo** – Obtain the project template and adjust the site configuration (`config.yml`, `site.config.js`, etc.).
2. **Configure AI Access** – Add your AI provider API key as a secret (`AI_API_KEY`) in the repository settings.
3. **Set Up GitHub Actions** – Enable the workflow file (`.github/workflows/generate.yml`) and verify the cron schedule.
4. **Define Templates** – Edit the markdown template (`article_template.md`) to match your preferred article layout.
5. **Deploy** – Connect the repository to a static‑site host (GitHub Pages, Netlify, Vercel) and push the initial commit.
6. **Monitor** – Review generated articles in the `posts/` folder and fine‑tune prompts if needed.

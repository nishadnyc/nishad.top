# Auto‑Generated Portfolio Blog Powered by AI and GitHub Actions

## Introduction  

Imagine a developer’s portfolio that never stays stale. Every time a new repository lands on GitHub, the site automatically creates a polished blog post that highlights the project, explains its purpose, and showcases key technical decisions—without the author writing a single line of content. This is exactly what the **AI‑driven personal blog/portfolio** does: it harvests a user’s GitHub activity, feeds it into a sophisticated language model, and publishes fresh articles on a daily schedule.

The result is a dynamic, self‑updating showcase that doubles as a marketing tool, a knowledge base, and a living resume.

---

## How It Works  

1. **GitHub Cron Workflow** – A GitHub Actions workflow runs on a daily schedule (`cron: '0 0 * * *'`).  
2. **Repository Discovery** – The workflow queries the GitHub API to collect metadata from all public repositories belonging to the owner (name, description, topics, recent commits, etc.).  
3. **AI Content Generation** – The collected data is passed to an AI model (e.g., OpenAI’s GPT‑4) that drafts a concise, engaging blog article. The model can:
   - Summarize the project’s goals  
   - Highlight standout features and technologies used  
   - Extract key code snippets or architectural decisions  
   - Suggest potential real‑world applications  
4. **Static Site Build** – The newly generated markdown file is added to the blog’s content folder. A static site generator (such as Astro, Hugo, or Next.js) rebuilds the site, injecting the fresh article into the archive and the homepage.  
5. **Automatic Deployment** – The updated site is deployed to a hosting platform (e.g., Vercel, Netlify, GitHub Pages) via another GitHub Action, making the article instantly visible to visitors.

All steps happen automatically, requiring zero manual intervention after the initial configuration.

## Getting Started  

1. **Fork the Repository** – Clone the repo to your own GitHub account.  
2. **Configure Secrets** – Add the following repository secrets:  
   - `OPENAI_API_KEY` – Access token for the language model.  
   - `GH_TOKEN` – Personal access token with `repo` scope for API calls.  
3. **Adjust the Workflow** – Edit `.github/workflows/generate.yml` to set the desired schedule or limit the repositories to a specific topic.  
4. **Customize Templates** – Modify the markdown template under `src/templates/article.md` to reflect your tone, branding, and desired metadata.  
5. **Deploy** – Enable the deployment action (e.g., Netlify/ Vercel) and push the first commit. The site will build and publish automatically.  

*Example of a workflow snippet:*

```yaml
name: Daily Blog Generation
on:
  schedule:
    - cron: '0 0 * * *'   # runs at 00:00 UTC every day
jobs:
  generate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Run Generator
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
          GH_TOKEN: ${{ secrets.GH_TOKEN }}
        run: npm run generate
      - name: Deploy
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GH_TOKEN }}
          publish_dir: ./public
```

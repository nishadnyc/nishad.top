# Automating My Technical Writing: A Self-Generating Portfolio

Maintaining a personal blog and portfolio is a constant struggle for developers. I often find myself deep in the flow of coding, committing features and fixing bugs, but I rarely have the time to sit down and write a comprehensive article explaining what I’ve actually built. To solve this, I built a system that turns my active development into published content automatically.

## What is this Project?

This project is the engine behind my personal blog and portfolio website. Rather than manually drafting posts, I have implemented an AI-driven pipeline that monitors my GitHub repositories and transforms my code changes into readable blog articles. 

By leveraging the power of Large Language Models (LLMs) and GitHub Actions, my website effectively writes itself based on the actual work I am doing in real-time.

## How It Works

The core of this system is a fully automated workflow that removes the friction between "coding" and "documenting."

1.  **Daily Scanning**: I utilize GitHub Workflow cron jobs configured to run once every day.
2.  **Repository Analysis**: The system scans my GitHub repositories to identify new activity, updates, or completed projects.
3.  **AI Generation**: Using an AI model, the system analyzes the codebase and the changes made, then synthesizes that technical data into a structured blog post.
4.  **Auto-Publishing**: The generated content is then pushed to my portfolio site, ensuring my public presence is always up-to-date with my latest technical achievements.

## Key Features

*   **Zero-Touch Content Creation**: I no longer need to manually write "What's new" posts; the AI handles the drafting process.
*   **GitHub Integration**: The system is tightly coupled with my version control, meaning the blog is a direct reflection of my commit history.
*   **Scheduled Updates**: Through the use of cron jobs, the site remains fresh without requiring me to trigger deployments manually.
*   **AI-Powered Synthesis**: The system doesn't just list commits; it uses an AI model to explain the purpose and functionality of the code.

## Potential Use Cases

While I built this for my personal portfolio, this architecture has several applications for other developers and teams:

*   **Automatic Changelogs**: Transforming raw commit messages into user-friendly release notes for clients.
*   **Developer Portfolios**: Helping engineers who struggle with writing maintain a consistent online presence that proves their activity.
*   **Internal Documentation**: Keeping internal team wikis updated by automatically summarizing changes in a private repository.
*   **Project Tracking**: Creating a daily diary of a project's evolution for stakeholders to follow without needing to read through git logs.

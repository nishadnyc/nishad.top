# Auto‑Generated Blog & Portfolio Powered by GitHub AI

## Introduction

A modern personal website should do more than showcase static pages—it should evolve alongside the developer’s work. This project combines a sleek portfolio site with an intelligent content engine that automatically writes fresh blog posts every day. By tapping into GitHub repositories and an AI language model, the site turns code commits, project releases, and repository metadata into readable, engaging articles without any manual authoring.

## Core Idea

- **Continuous Content Creation** – Every 24 hours a GitHub Actions workflow scans the owner’s public repositories, extracts relevant information, and feeds it to an AI model that drafts a blog post.
- **Self‑Hosted Portfolio** – The generated articles are seamlessly integrated into a personal blog/portfolio site, keeping the portfolio up‑to‑date with the latest projects and achievements.
- **Zero‑Maintenance Publishing** – Once configured, the system runs autonomously, requiring no ongoing human intervention.

## How It Works

1. **GitHub Workflow Trigger**  
   A cron‑based GitHub Actions workflow executes once per day.  

2. **Repository Discovery**  
   The workflow enumerates the user’s public repositories via the GitHub API, gathering metadata such as description, recent commits, releases, and topics.

3. **Prompt Generation**  
   For each repository, a structured prompt is built that captures the project’s essence, technical highlights, and recent activity.

4. **AI Content Generation**  
   The prompt is sent to a large‑language‑model (LLM) service (e.g., OpenAI’s GPT family). The model returns a well‑formed markdown article, complete with headings, code snippets, and contextual explanations.

5. **Site Integration**  
   The newly created markdown files are committed back to the repository’s `posts/` (or equivalent) folder. A static site generator (such as Hugo, Jekyll, or Astro) picks up the files on the next build, making the fresh article live on the portfolio site.

6. **Deployment**  
   The site is hosted on a static‑site platform (GitHub Pages, Netlify, Vercel, etc.), delivering the updated content instantly to visitors.

## Key Features

- **Daily Automated Blogging** – No manual writing; the AI produces one or more posts each day.
- **Repository‑Driven Content** – Articles are tightly coupled to real code, ensuring relevance and authenticity.
- **Customizable Prompts** – Tailor the AI prompt to match your tone, depth, or target audience.
- **Static‑Site Friendly** – Output is plain markdown, compatible with any static site generator.
- **Version‑Controlled Content** – Generated posts live in the same git repository, enabling review, edits, or rollbacks.
- **Workflow Transparency** – The entire pipeline is defined in a declarative GitHub Actions YAML file, making it easy to audit and extend.

## Technical Stack

| Layer | Technology |
|-------|------------|
| **Automation** | GitHub Actions (cron trigger) |
| **Data Retrieval** | GitHub REST API / GraphQL |
| **AI Engine** | Large Language Model (e.g., OpenAI GPT‑4) |
| **Content Format** | Markdown |
| **Site Generation** | Static site generator of choice (Hugo, Jekyll, Astro, etc.) |
| **Hosting** | GitHub Pages / Netlify / Vercel |
| **Version Control** | Git (self‑hosted repository) |

## Getting Started

1. **Fork the Repository** – Clone the repo to your own GitHub account.
2. **Configure Secrets**  
   - `OPENAI_API_KEY` (or equivalent for your chosen LLM)  
   - `GH_TOKEN` (optional, for private repository access)  
3. **Adjust the Workflow** – Edit `.github/workflows/auto‑blog.yml` to set the cron schedule, repository filters, and prompt template.
4. **Select a Site Generator** – If not already set up, initialize a static site generator and point it at the `posts/` directory.
5. **Deploy** – Enable GitHub Pages or connect the repo to a hosting service. The first run of the workflow will generate an initial post.
